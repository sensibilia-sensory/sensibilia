# Collection and form contracts

`contracts/openapi.json` is generated by `scripts/export_contracts.py`; the live `/openapi.json`
is authoritative for the running application. Configuration schema v1 is frozen in
`migrations/versions/hedonic_v1.json`; changing it requires a new method version and migration.
Pydantic additionally checks unique question IDs, nonblank labels, and response-state consistency.
Unrecognized object fields are rejected.
The seven additional methods have frozen schemas in `migrations/versions/methods_v1.json`.
See [method configurations, response states, serving plans and exports](method-library.md).
Study forms have a separate frozen schema in `contracts/form_v1.json`; see
[form routing, values and collection order](study-forms.md).

## Researcher API

All endpoints below require the server's researcher bearer credential.

| Method | Path | Result |
| --- | --- | --- |
| GET | `/test-types` | Registered method versions, schemas, and implementation metadata |
| GET | `/test-types/{test_type_id}` | A method version's schema and metadata |
| GET | `/studies?search=&limit=50&offset=0&archived=exclude` | Browse studies with versions and open-assessment counts; case-insensitive title search; `archived` is `exclude`, `only` or `include` |
| POST | `/studies` | Create identity and initial draft version; HTTP 201 |
| GET | `/studies/{study_id}` | Identity and versions ordered by revision number |
| PATCH | `/studies/{study_id}` | Replace title/description on study identity and current draft |
| POST | `/studies/{study_id}/drafts` | Clone latest publication into next draft; HTTP 201 |
| POST | `/studies/{study_id}/samples` | Add coded product to current draft; HTTP 201 |
| GET | `/studies/{study_id}/versions/{version_id}/samples` | Read researcher product catalog |
| POST | `/studies/{study_id}/tests` | Append configured test to current draft; HTTP 201 |
| GET | `/studies/{study_id}/versions/{version_id}/tests` | Inspect tests in a draft or publication |
| PUT | `/studies/{study_id}/tests/{test_id}` | Replace a current draft test's configuration |
| DELETE | `/studies/{study_id}/tests/{test_id}` | Remove a current draft test and compact positions; HTTP 204 |
| PUT | `/studies/{study_id}/versions/{version_id}/form` | Replace current draft flow; body `{"form":...}` or explicit null |
| POST | `/studies/{study_id}/publish` | Validate and freeze current draft |
| POST | `/studies/from-samples` | Create a study with its samples, per-sample methods and one loop over the samples, atomically; HTTP 201 |
| POST | `/studies/{study_id}/close` | Stop new assessments; optional `end_open_assessments` ends those in progress |
| POST | `/studies/{study_id}/reopen` | Allow new assessments again |
| POST | `/studies/{study_id}/archive` | Hide from the study list; refused while assessments are in progress |
| POST | `/studies/{study_id}/restore` | Bring an archived study back |
| GET | `/booth-board` | Each active tablet with its booth, assessor, current study version and a plain stage sentence (no answers) for Run study; a tablet with an open sample request also carries its codes, product labels, preparation and request state |
| POST | `/booth-board/operations` | Acknowledge or serve an open sample request from the booth board with the researcher key (same body and revision check as `/operator/operations`; tablets and the operator key are refused here) |
| POST | `/sessions/{session_id}/end` | Staff end an assessment in progress; answers recorded before the end still sync |
| POST | `/sessions` | Provision session on an explicit published version; HTTP 201 |
| GET | `/sessions/{session_id}/serving-plan` | Private frozen preparation order, labels, codes and answer key |
| GET | `/studies/{study_id}/responses?limit=100&offset=0` | Events with provenance and current flags |
| GET | `/studies/{study_id}/form-responses?limit=100&offset=0` | Atomic block submissions with version/session context |
| POST | `/questionnaire-items` | Save a question or information step to the item bank for reuse |
| GET | `/questionnaire-items` | List saved steps (`include_archived`, `limit`, `offset`) |
| POST | `/questionnaire-items/{item_id}/archive` | Hide a saved step; nothing is deleted |
| GET | `/studies/{study_id}/export` | Study data as UTF-8 CSV: `format=long` (default, entire history), `wide`, or `r` (one plain value per cell for R, current answers by default) |
| GET | `/analysis/status` | Whether the optional analysis add-on (R) is `ready`, `missing`, `needs_update` or `broken`, with a sentence for people |
| POST | `/analysis/power` | Assessors needed (or power) for a triangle, duo-trio or 2-AFC test; arithmetic only, works without the add-on |
| GET | `/studies/{study_id}/versions/{version_id}/analyses/suggested` | Analyses that apply to the tests of a published version, with default settings |
| POST | `/studies/{study_id}/analyses` | Freeze the current answers (or use `snapshot_id`) and queue one analysis, atomically; HTTP 201; 409 while the add-on is not ready |
| GET | `/studies/{study_id}/analyses` | Analyses run for the study, newest first |
| GET | `/studies/{study_id}/analyses/{job_id}` | One analysis: status, receipt, typed result and its plain-language answer, warnings and explanation |
| GET | `/studies/{study_id}/analyses/{job_id}/report?format=xlsx\|docx` | Excel workbook or Word report of a finished analysis |
| GET | `/studies/{study_id}/analyses/{job_id}/figures/{name}` | A PNG figure drawn by R |

A study has at most one draft. Whole-study deletion is not implemented: studies are closed and archived instead. Sample assignments and
product order freeze at session provisioning. Draft metadata edits preserve earlier published snapshots.
Removing a test is allowed only in the current draft; remaining test IDs are preserved and their
positions are compacted. Remove a referenced flow block before deleting its sensory configuration.
Study browsing orders by newest creation time, then ID, with limits 1–1000;
search treats SQL wildcard characters literally. Legacy session order is the study tests' configured order; forms supply screen routes. Session
provisioning returns its bearer token once; the token is not returned by the package API.
API pagination permits limits from 1 to 1000; CSV is unpaginated and buffered in memory for the
initial laboratory workload. Large streaming exports will require explicit dataset snapshot handling.

## Restricted tablet API

These require the credential for the path's exact session ID; a researcher credential does not
substitute for a session credential. Session credentials cannot call researcher endpoints.

| Method | Path | Result |
| --- | --- | --- |
| GET | `/sessions/{session_id}/test` | Assigned package; schema 1 legacy, 2 hedonic/form, 3 new method library |
| GET | `/sessions/{session_id}/progress` | Current form step, submitted path and terminal outcome |
| POST | `/sessions/{session_id}/form-events` | Atomic ordered Continue submissions; 1–100 events |
| POST | `/sessions/{session_id}/responses` | Atomic ingest of 1–500 events and committed acknowledgements |
| POST | `/sessions/{session_id}/complete` | Complete legacy required tests or record the form's reached terminal outcome |

The package includes the session, its fixed presentation order, frozen title and description,
configured tests, method identifiers/versions and schemas, and `samples`/`assets` arrays. These
arrays are empty in legacy v1. Schema 3 contains public coded products and frozen `assignments`;
comparison slots expose codes without product identity or answers. Image assets remain empty.
Non-null `sample_id` must belong to both the session version and the configured attribute test.
Questions and instructions are configured by researchers. Each test
instance has a stable UUID; repeats of the same method are separate instances.

## Events, correction history, and retries

Required event fields: `client_event_id` (UUID), `study_test_id` (UUID), `question_id`, `value`,
and `recorded_at` (timezone-aware ISO 8601). Optional fields: `sample_id` (UUID or null) and
`supersedes_event_id` (UUID or null). Timestamps normalize to UTC; the client time records when
the observation was made and `received_at` records server ingestion. Client clocks are not assumed
to be synchronized. No artificial future/past timestamp cutoff is applied to offline observations.

Hedonic values are `{"state":"rated","rating":1}` through rating 9, or
`{"state":"skipped","rating":null}` when the configured `allow_skips` is true. Missing means
no event exists for the question. Zero is invalid for this method; unselected and selected/unrated
states are defined separately for CATA and RATA in the method guide. Missing must not be inferred
from null ratings. Explicitly allowed skips satisfy completion, including required questions.

An initial event has no predecessor. A correction must reference the current event for the same
session, test, question, and sample context. New UUIDs are required for corrections; stale predecessors
and ambiguous replacement events produce HTTP 409. History is append-only. Exact retries remain
valid after completion; new observations and corrections are refused for closed sessions. For a
form, ratings and corrections are limited to its current test block; Continue freezes that block.

Whole batches commit or roll back together. A client must retain all events on a non-success response.
On success each acknowledgement supplies `client_event_id`, server `response_id`, and `accepted`
or `duplicate`. Semantic identity uses validated fields and normalized UTC timestamps. JSON key
order and omitted default nulls do not change identity. Event IDs are globally unique; attempts to
reuse an event in another session produce 409.

HTTP 401: absent/invalid credential or wrong session. HTTP 404: unknown researcher resource.
HTTP 409: lifecycle conflict, changed retry payload, or stale correction. HTTP 422: invalid schema,
unknown question, disallowed skip, unpublished provisioning, or wrong assigned test/version.
HTTP 503 with `Retry-After: 1`: SQLite writer contention exceeds its busy timeout. Retry the
original UUIDs after connectivity/server availability recovers.

## CSV interpretation

`format=r` is a derived, JSON-free view for R and spreadsheets: one row per value, a `state` column for
skipped, missing, unselected and selected, and an empty `value` when there is none (NA in R). The text below
describes the long export.

One row per attribute/choice event (including superseded events), form Continue event or matrix row.
Flash profiles expand into descriptor/product rows; Napping maps into product/coordinate rows,
retaining the full atomic JSON and event ID on every row. See the method guide for added columns.
Columns preserve event/response IDs,
study ID, version ID and number, session and assessor code, configured test ID, method key/ID/schema
version, question ID, sample context, value, client/server timestamps, predecessor ID, and current
flag. Decode `value_json` and `sample_id_json` with a JSON parser; `sample_id_json` contains JSON
`null` in v1. An empty predecessor column means no predecessor; `is_current` is `True` or `False`.
RFC-style CSV quoting preserves commas, quotes, and line breaks in fields. Form columns and
matrix missing/selected/skipped states are described in [the form contract](study-forms.md).

Unanswered sensory questions and unvisited form blocks have no rows. A submitted matrix exports
absent optional rows with an explicit missing state. Use the published study package
to determine expected questions; they are distinguishable from recorded skip events. Consumers
must select `is_current` when analyzing corrected answers, or explicitly analyze the event history.
Raw text is preserved, so spreadsheet consumers should import text columns without formula evaluation.
