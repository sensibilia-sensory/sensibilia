# Sensibilia staff runbook, institution-managed deployment — schema revision 0013

> For the optional institution-managed stack. Laboratories running the standard install (`./docker-up.sh`) use the [small-laboratory guide](standard.md).

IT fills in this sheet before collection: **support contact**, **hostname**, **backup target**, **release digest**, **approved device/browser**, **validated booth capacity**. All commands run from the installed release directory with Python 3.13+ and Docker Compose available. IT provides shortcuts for the commands below; staff do not compose shell commands. No real sessions until the deployment and the tablets have been validated.

| Task                | Prepared command / staff sequence                                                                                                                                                                                                                                                                                                                                                                                                                               | Stop rule                                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Install             | IT supplies deploy/private/lab.env, certificate and token files, separate writable backup target. Run python scripts/laboratory.py initialize, then python scripts/laboratory.py start, then python scripts/laboratory.py backup. Open the configured HTTPS hostname on the tablet; prepare a synthetic assessment and rehearse/sync/export.                                                                                                                    | Any certificate warning, failed health/backup or reconciliation difference: stop and contact support.                                        |
| Daily check         | Run python scripts/laboratory.py status (last verified backup no older than two hours). Confirm IT's separate encrypted copy. Check time, tablet persistence, origin and pending queues.                                                                                                                                                                                                                                                                        | Missing/stale/failed backup blocks a new collection run. Outside collection, IT may use the 26-hour status check described in operations.md. |
| Backup now          | Run python scripts/laboratory.py backup before changes. Record the returned backup filename.                                                                                                                                                                                                                                                                                                                                                                    | Failed backup: preserve data, stop starting assessments, contact support.                                                                    |
| Upgrade             | Finish and synchronise all tablets; confirm zero pending on each. Record old digest. IT updates APP_IMAGE to reviewed new digest. Run python scripts/laboratory.py upgrade --previous-release OLD_IMAGE_DIGEST. The command stops collection and verifies a backup before migration; it leaves collection stopped. On success, run Start, Backup now, and synthetic rehearsal/export before reopening collection.                                               | On any failure leave collection stopped. Support restores the pre-upgrade archive with its matching old release; never blindly downgrade.    |
| Restore             | Stop collection with python scripts/laboratory.py stop. Preserve old DATA_VOLUME and tablet queues. Support sets APP_IMAGE to the archive's release and DATA_VOLUME to a new isolated volume in a separate configuration. Run python scripts/laboratory.py --config RESTORE_CONFIGURATION restore --archive BACKUP_FILENAME.db, then Start with that same configuration. Verify integrity/counts/packages/UUIDs/CSV and record operator, duration and incident. | Existing restore target or wrong release is refused. Never clear tablet data; original event UUIDs are needed for reconciliation.            |
| Certificate renewal | Named IT owner replaces full chain/key, recreates only tls, checks expiry/SAN/chain with every approved browser at the laboratory hostname and rehearses secure installation/cache.                                                                                                                                                                                                                                                                             | A warning bypass does not count as trust. Failed TLS blocks collection.                                                                      |

IT schedules hourly verified backups during collection and nightly otherwise; alerts on failed jobs or stale receipts. Retention requires institutional approval; encrypted off-disk replication and monthly restore drills are separately monitored. Keep this sheet with the institutional contact and rehearsal screenshots; repository synthetic captures are examples, not proof for your laboratory.
